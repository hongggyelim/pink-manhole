## Project

분홍맨홀 (pink-manhole): a mobile-first responsive web app where citizens report pink manholes with photos and a location. All reports are public. No sign-up is needed to report. It runs on free tiers only (Vercel Hobby, Supabase Free, GitHub).

Current scope is **data collection only**. Submitting to 국민신문고 is out of scope for now, but the `submitted` status is kept for later.

## Commands

```bash
pnpm dev            # dev server (Turbopack)
pnpm build          # production build — run before pushing
pnpm lint           # ESLint
supabase db push    # apply supabase/migrations to the linked remote project
supabase migration new <name>   # create a new migration (never edit applied ones)
```

There is no test runner yet.

## Stack

Next.js 16 (App Router, `src/`), React 19, TypeScript, Tailwind v4, shadcn/ui (`src/components/ui`), Supabase (Postgres + Storage), zod. Next 16 renamed middleware to **proxy** (`src/proxy.ts`). Check `node_modules/next/dist/docs/` before using Next APIs.

The map provider is not decided yet (Kakao or Naver). Keep all map SDK code behind an adapter in `src/features/map/`, and all geocoding behind `src/server/services/`.

## Architecture rules

- **Reads are public, writes go through the server.** Clients read `reports`, `report_photos` and `report_status_history` directly with the publishable key. RLS only exposes rows where `is_hidden = false`. No table has an anon or authenticated write policy. Every insert or update happens in Route Handlers or Server Actions using `createAdminClient()` (`src/lib/supabase/admin.ts`, which bypasses RLS).
- `report_private` holds abuse-prevention data (salted IP hash, user agent, idempotency key). Clients can never read it. Never store raw IPs.
- Photos: compress and re-encode in the browser (canvas → JPEG/WebP, which also strips EXIF), with at most `MAX_PHOTOS` = 3 per report. Upload them at final submit using server-issued signed upload URLs to the public `report-photos` bucket. List and map views use thumbnails only, to save egress.
- The location saved is the pin the user confirms on the map, not raw GPS. The server validates the coordinates against Korea's bounds and does reverse geocoding (`sido` and `sigungu` are used for region filters).
- `report_no` (e.g. `PM-261103-7K3Q`) is generated by a DB default. It is a lookup convenience, not a secret or credential.
- Status flow: `received → reviewing → submitted → resolved`, plus `rejected`. Labels live in `src/shared/constants.ts` and must match the `report_status` enum. Only admins change status, and each change writes a `report_status_history` row.
- Admins are Supabase Auth users listed in `admin_users`, added manually. There is no admin sign-up.
- Directory roles: `src/app` handles routing and composition only; `src/features/*` holds UI and client logic per feature; `src/server/*` holds server-only services (import `server-only`); `src/shared` holds zod schemas, types and constants shared by client and server.

## Environment

Copy `.env.example` to `.env.local`. The same variables must be set in Vercel. `SUPABASE_SECRET_KEY` must never use the `NEXT_PUBLIC_` prefix.
